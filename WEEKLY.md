# Еженедельная проверка бэклога (инструкция для Claude)

Запускается автоматически по понедельникам (~08:40 по Вильнюсу): запланированная задача будит постоянную облачную сессию «PSN бэклог: еженедельная проверка (постоянная сессия)», к которой подключён этот репозиторий (ветка main). Человека рядом нет: **вопросов не задавать**, решать по этой инструкции. Владелец — PSN-аккаунт `Anton_games337` (уровень 558), аккаунт русский: купить в PS Store ничего нельзя.

## Как устроен трекер

- `data/trophies/`, `data/titles.json`, `data/profile.json` — данные PSN. Каждый день их обновляет GitHub Action **Update backlog** (секрет `PSN_NPSSO`). Эта сессия PSN сама **не выгружает**: токена здесь нет.
- `data/estimates/` — оценки по гайдам (формат: `docs/estimates-schema.md`).
- `data/overrides.json` — решения владельца и проверенные статусы серверов (`game_overrides[id].servers`, `all_online`, `online_dead`, `still_possible`, `notes_ru`). Решения владельца (`unobtainable_groups`, `trophy_overrides` с пометкой «по словам владельца») **не менять**.
- `python3 scripts/build.py` собирает README, ONLINE.md, UNOBTAINABLE.md, `games/`, `data/history.csv`, `charts/burndown.svg`.
- Письма: любой **новый** файл в `reports/weekly/` или `reports/alerts/`, запушенный в `main`, отправляет Action **Email reports** через Gmail SMTP. Самой сессии слать почту не нужно.
- Дедлайны: `data/deadlines.json` → `calendar/deadlines.ics` (владелец подписан на этот календарь в Google Calendar).

## Шаги

### 1. Состояние синка
- Сравнить `fetchedAt` в `data/profile.json` с сегодняшней датой. Старше 2 дней — **проблема**: синк не работает. Посмотреть последние запуски:
  `gh api repos/AntonGames/psn-backlog/actions/workflows/update.yml/runs?per_page=5 --jq '.workflow_runs[] | [.created_at,.conclusion] | @tsv'`
  Типичная причина — не задан или истёк `PSN_NPSSO` (живёт ~60 дней). В тревоге объяснить, как обновить секрет: шаги есть в `.github/workflows/update.yml`.
- Проверить, что письма доходят: последние запуски `notify.yml`. Если они падают или пишут «MAIL_USERNAME / MAIL_APP_PASSWORD не заданы», указать это в отчёте.

### 2. Сборка
`python3 scripts/build.py`. Ошибок быть не должно.

### 3. Новые игры и DLC без оценки
Найти игры с трофеями категории «❔ нет оценки» (в README строка «❔ Без оценки» или `cat == unknown`). Для каждой — исследование по `docs/estimates-schema.md` (до ~6 запросов на игру) и файл `data/estimates/<id>.json`. Если у игры уже есть оценка, но добавились новые трофеи (DLC), дописать записи для новых id и пересчитать часы.

### 4. Онлайн и сервера (главное)
Для **каждой** игры из `ONLINE.md` (невыбитый онлайн на живых серверах) и always-online игр проверить, нет ли:
- анонса закрытия серверов или онлайна (дата!), конца поддержки, отключения режимов или рейтингов;
- региональных блокировок (пример: Konami с 15.06.2026 блокирует онлайн MGSV для РФ/РБ);
- массовых проблем с онлайном в последние недели.

Источники: страницы издателей (EA `https://www.ea.com/service-updates`, Ubisoft, Konami, Rockstar, Sony, Capcom, Bandai Namco, Codemasters), новостные сайты, Stratege (даты свежих платин). Cloudflare не обходить.

Результат записать в `data/overrides.json` → `game_overrides[<id>].servers`: `{"status": "up|partial|shut_down|unknown", "detail": "Проверено ГГГГ-ММ-ДД: …", "source": "URL"}`.
- Если онлайн уже закрыт: `online_dead: true`, а исключения перечислить в `still_possible`.
- Если закрытие **анонсировано**: оставить `up`, но в `detail` указать дату. Это **дедлайн**.

### 5. Делистинг
Проверить, не снимают ли с продажи игры из бэклога и нужные платные DLC (README → «Платные DLC в остатке», поле `dlc_required`). Анонс снятия с продажи — **риск или дедлайн**: успеть скачать купленное и не потерять доступ.

### 6. Цена DLC The Division 2
Условие владельца: Battle for Brooklyn + Echoes of Central Park вместе ≤ **492 ₽** в PS Store RU (`store.playstation.com/ru-ru`). Если цена видна и условие выполнено — **тревога** («можно покупать»). Если проверить не удалось, одна строка в отчёте, без тревоги.

### 7. Пересобрать
`python3 scripts/build.py` после всех правок.

### 8. Еженедельный отчёт — `reports/weekly/ГГГГ-ММ-ДД.md` (дата запуска; если такой файл уже есть — `ГГГГ-ММ-ДД-2.md`, чтобы файл был новым и ушло письмо)
Это тело письма: файл превращается в HTML. Держать **строго** этот шаблон, только заголовки `#`/`##`/`###`, списки и **жирный**, без «висящих» абзацев-перечислений:

```markdown
# Неделя ДД.ММ–ДД.ММ.ГГГГ

## Итоги
- Выбито: **N трофеев**, платины: … (или «нет»). Закрыто на 100%: … (или «нет»).
- Остаток: **~H ч** (−X ч за неделю), темп **X ч/нед** против цели 20 → при таком темпе ~N недель.

## Онлайн и сервера
- <игра> — что изменилось и источник. (Если ничего: одна строка «Без изменений, все сервера живы».)

## ⚠ Риски и дедлайны
- **<игра>** — что случилось, **дата**, что сделать. (Или «Нет».)

## План на неделю (~20 ч)
1. **<Игра> <платформа> · <трофей>** — что сделать. ~N ч.
2. … (3–5 пунктов)

### С напарником (по желанию)
- **<Игра> · <трофей>** — что нужно. ~N ч.
```

Откуда данные: трофеи и платины за 7 дней — `data/history.csv`, `earnedAt` в `data/trophies`, `lastUpdated` в `data/titles.json`. Приоритет плана: (а) онлайн под риском или с дедлайном; (б) быстрые победы и почти закрытые игры; (в) игры, в которые сейчас играют (свежий `lastUpdated`). Пункты с напарником — только в подраздел «С напарником». Пустой подраздел не выводить.

### 9. Тревоги — `reports/alerts/ГГГГ-ММ-ДД.md` (при совпадении имени — суффикс `-2`)
Создавать **только** при новом дедлайне, проблеме или риске: анонс закрытия, блокировка, делистинг, сломанный синк, выполненное условие цены. Ничего нового (сравнить с прошлыми файлами в `reports/alerts/`) — файл не создавать. В тексте: что случилось, дата дедлайна, что сделать, источник.

Каждый **датированный** дедлайн добавить в `data/deadlines.json`:
`{"date": "ГГГГ-ММ-ДД", "title": "PSN: <игра> — <что>", "details": "что сделать", "url": "источник", "added": "ГГГГ-ММ-ДД"}`.
Перед этим проверить, нет ли уже такой записи; прошедшие даты не удалять. `build.py` соберёт из файла `calendar/deadlines.ics`. На этот календарь владелец подписан в Google Calendar, напоминания по почте настроены у него. Ближайшие дедлайны также попадают в README.

Если в сессии есть инструменты Google Calendar (найти через ToolSearch по «calendar»), можно дополнительно создать событие в основном календаре (primary): весь день, название как в `title`, `overrideReminders` — email за 43200, 10080 и 1440 минут. Сначала `search_events` по «PSN:», чтобы не задвоить. Без этих инструментов достаточно `deadlines.json`.
